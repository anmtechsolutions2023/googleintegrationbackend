Per-dish notes stay with the dish

“No onions” belongs to the Butter Chicken, so it prints under that line — where the cook making it will read it.

Order-level instructions print below the items

Deliberately after the dishes: a cook reads what to make first, then how the customer wants the whole order treated.

“No cutlery” gets its own box

It is a flag, not a phrase to hunt for in a sentence — and it is acted on by whoever bags the order, who is not reading the cooking notes above it.

You control what prints

Both lines are switches on Receipt Format → Kitchen ticket, alongside the ones you already have. Turn either off per branch.

The ticket is a snapshot

What prints is copied at the moment the ticket fires, exactly like the item list. If somebody edits the order afterwards, paper already on the pass does not silently change under the cook.

“Item out of stock” asks which dish
Zomato needs to know which one ran out, so this reason won’t send until you tick the items. The other five don’t ask.

These six are yours to edit on Setup → Rejection Reasons. Each carries a portal code field, filled in during Zomato certification — deliberately blank now, because inventing a code would push a value their API rejects on the first refusal.
